# 프로젝트 상세 배정 브라우저 검증 (2026-10-13)

사용자가 Codex 직접 브라우저 검증을 명시 허용했다. 내장 브라우저와 별도 WEB/API를 사용했으며 실제 개발 DB·기존 실행 서버는 유지했다. 앱 코드/모델/API 계약은 이번 작업에서 변경하지 않았다.

## 1. 검증 환경과 데이터 경계

- 기존 WEB `http://127.0.0.1:3000`은 조회로만 열었다. 저장 검증은 WEB 13000 → API 18001 → 사본 SQLite `copy.db`에만 연결했다.
- 실제 DB를 SQLite 읽기 전용 연결의 backup으로 복사했다. WEB 소스, 공통 설정/패키지, 별도 `.next` 캐시와 공개 환경변수를 `.runtime/browser_assignment_check/20261013_135344/workspace`에 구성했다. 원본 `.env`/웹 캐시는 수정하지 않았다.
- 기록/사본/스크린샷: `.runtime/browser_assignment_check/20261013_135344/`의 setup.json, result.json, copy.db, 01-retained-values.jpg, 02-invalid-date.jpg, 03-overlap-warning.jpg.
- 실제 DB의 검증 전후 SHA256은 모두 `275849120cb1320ce88487bf669708a2479f97a33a2b72032f4f93c5e28eef5a`로 동일하다. 실제 원본의 인력 18/프로젝트 137/배정 39/진행이력 90을 보존했다. 사본에만 검증 배정 1건과 등록·비고 수정·MM/확도 수정 이력 3건을 추가했다.
- 검증 대상은 P2026001의 기존 테스트 인력이다. 새 예정 배정 기간은 2026-11-01~2026-11-30이다. 사용자가 만든 취소 이력은 수정하지 않았다. 검증 종료 후 Codex가 만든 브라우저 탭과 임시 WEB/API를 종료했고 기존 3000/8001 서버는 유지했다. 백업·증거 파일은 Git 제외 폴더에 보존한다.

## 2. 실제 브라우저 검증 결과

| 항목 | 조작 및 확인 | 결과 |
|---|---|---|
| 비고 수정 | 비고만 변경, 변경 항목 1개 검증 → 저장 → 수정 창 재진입 | 새 비고 유지 |
| 월 기준 MM/확도율 | 월 기준 MM 1.5, 확도율 50 입력 → 변경 항목 2개 검증 → 저장 → 페이지 전체 새로고침 → 수정 창 재진입 | 1.5/50 및 비고 유지 |
| 날짜 입력 오류 | 종료일을 시작일 이전으로 변경 후 검증 | 한국어 오류 표시, 저장 비활성 |
| MM 범위 오류 | -1 MM 입력 후 검증 | 한국어 범위 오류 표시, 저장 비활성 |
| 확도율 범위 오류 | 101% 입력 후 검증 | 한국어 범위 오류 표시, 저장 비활성 |
| 정밀도 오류 | 1.555 MM 입력 후 검증 | API 422 오류 표시, 저장 비활성 |
| 기간 중복 | 동일 인력의 11/15~12/15 배정으로 검증 | 겹침 1건/기간/확인 체크 표시; 미확인 저장 비활성 → 확인 시 활성 → 해제 시 비활성. 저장하지 않음 |
| 완전 중복 | 동일 프로젝트·인력·유형·역할·11/01~11/30 기간으로 검증 | API 409 완전 중복 오류, 저장 비활성. 저장하지 않음 |
| 실패 후 원본 값 | 오류/중복 모달 닫기 후 저장된 배정 수정 창 재진입 | 기존 1.5/50/날짜/비고 그대로, 추가 배정 없음 |

- 사본 DB 읽기 검증에서 11월 투입 MM 1.5, 가중 MM 0.75를 확인했다. 현재 10월의 목록 MM이 0.00인 것은 미래 11월 예정 배정이므로 정상이다. FK 검사 오류 0건, 배정은 정확히 1건만 증가하고 로그는 정확히 3건 증가했다.
- 내장 브라우저의 오류 수준 콘솔 로그는 0건이었다. production build는 실행하지 않았으며 임시 WEB의 dev 컴파일로 화면을 확인했다.
- 보완 항목: 소수점 3자리 오류 문구가 `Decimal input should have no more than 2 decimal places`로 영어 표시된다. 기능적으로 저장은 차단하지만 한국어 사용자 안내는 후속 보완이 필요하다. 이번 작업은 검증과 하네스 원칙 수정 범위로 제한했다.

## 3. 하네스 변경

- [dev_guide.md](dev_guide.md) 4절: Codex가 기본 브라우저 검증을 수행하고 사용자는 필요한 환경/실무 추가 검증을 담당한다. 저장 검증은 임시 DB/실제 사본의 별도 환경에서 진행하고 원본 DB/실행 서버를 유지한다. 도구/환경 제약이 있으면 미검증 항목·사유·추가 확인 방법을 보고한다.
- [verification_guide.md](verification_guide.md) 1·7절: 기존의 Codex 브라우저 검증 금지 문구를 제거하고 dev_guide의 기준으로 연결했다. 정책을 별도 복제하지 않고 핵심 가이드와 책임을 맞췄다.
- 문서 변경의 diff/참조 정합성을 확인했다. 앱 코드/타입/운영 의존성을 바꾸지 않아 별도 타입 검사·린트·백엔드 전체 테스트는 반복하지 않았다. 실제 브라우저 작업과 사본 데이터 정합성으로 요청된 동작을 검증했다.
